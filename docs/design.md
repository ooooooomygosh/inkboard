# 设计思路

这份文档讲 InkBoard 为什么长成现在这样：每个部分在解决什么问题，做过哪些取舍，哪些路走不通。想照着做一个类似东西的人，读这一篇比读代码快。

## 1. 出发点：注意力比信息更稀缺

做研究、写代码的人每天面对的不是信息太少，而是要处理的东西散在太多地方：

- 终端里两三个 Agent 在跑，其中一个已经停下来等你批准，你不知道；
- 日历、邮箱、待办各管一摊，早上要花二十分钟拼出“今天到底干什么”；
- AI 订阅的额度什么时候用完、API 余额还剩多少，要分别登录去看；
- 手机和电脑本身就是最大的干扰源，打开它们去“看一眼”，往往就回不来了。

所以目标不是再做一个 App，而是一块**不需要主动打开**的屏幕：放在显示器旁边，抬眼就是全局；真正需要你的事情会出现在固定位置，其余时间它安安静静。

墨水屏正好合适：不发光，不闪烁，内容不变时不耗电，看起来像一张纸。很多人抽屉里都有一台不再读书的电纸书阅读器，硬件是现成的。

## 2. 三条分工

整个系统按“谁能拿到这份数据”切成三块：

| 部分 | 只做什么 | 为什么 |
|---|---|---|
| 阅读器 | 显示、点按、控制刷新和前光 | 设备性能弱、浏览器内核旧，越少逻辑越稳 |
| 云端（Cloudflare Worker + D1） | 聚合数据、跑 AI、存状态、托管编辑器和手机页 | 一直在线；Mac 合盖、手机没网时看板照常更新 |
| Mac | 采集只有本机才有的东西：Agent 会话、订阅额度、邮件、笔记 | 这些数据不在任何公开 API 里 |

三者之间只有 HTTP。任何一端掉线，另外两端照常工作；屏幕显示最后一次拿到的数据，并标出“X 分钟前”，不会白屏，也不会显示错的东西。

## 3. 为什么是 WebView，而不是原生界面或服务端渲染图片

比较过几条路：

| 做法 | 问题 |
|---|---|
| 系统浏览器打开一个网页 | 有地址栏、会息屏、不开机自启、控制不了刷新，残影越积越多 |
| Kiosk 浏览器 | 用不到厂商的刷新接口，高级功能收费 |
| 服务端渲染整屏 PNG（TRMNL 一类） | 整屏图片没法点按，刷新间隔以分钟计，Agent 的实时状态做不了 |
| 原生 App 自己画界面 | 改一次布局就要重新打包，迭代太慢 |
| **极简壳 App + 全屏 WebView** | 布局用 Web 写，改完刷新即生效；壳负责 Web 做不到的事 |

壳 App 只有几百行 Java，不用 Gradle：开机自启、作为桌面、全屏、看门狗、断网页面；再加上几个 Web 碰不到的能力，通过 `window.Ink` 暴露给页面：

- **刷新模式**：厂商 ROM 通常在 framework 里藏着私有的 e-ink 接口（`setRefreshMode`、`forceGlobalRefresh` 之类）。壳用反射调用：文字和小区域变化用快速局刷，翻页和每 30 分钟一次用全刷清残影。
- **前光和色温**：直接写驱动暴露的节点，可以按时间段自动调。
- **电池保养**：常年插电时充到 80% 停、低于 70% 再充。
- **系统设置**：插电常亮、时区、关闭 USB 模式选择弹窗。

旧阅读器自带的 WebView 往往停在很老的版本。前端按旧内核编译能跑，但如果 ROM 用公开的 AOSP 测试密钥签名，可以把新版 Chromium WebView 改包名、重签名后作为系统 WebView 的普通更新装上去，不用 root，随时可以卸载回原版。细节见 [device.md](device.md)。

## 4. 刷新：墨水屏上最容易做坏的地方

墨水屏的难点不在显示，而在“什么时候刷、怎么刷”：

- **数据不变就不动**。设备带 ETag 轮询，云端按数据内容算 ETag，没变就回 304，页面不重绘，屏幕不闪。
- **频率跟着情况变**。平时 30 秒一次；有 Agent 在跑时 10 秒一次；夜间切到一张只有时间、天气和明天第一件事的夜间屏，点一下才回到看板。
- **局刷和全刷分开**。局部变化用快速波形，累计一定次数或每隔半小时做一次全刷，残影不会积累。
- **设计按墨水屏来**：只用黑、白和少量灰；没有动画；数字用等宽字体，变化时不抖；卡片边界用细线，不用阴影。

## 5. “需要你”：一个收件箱

这是整个项目最核心的一块。所有“需要人本人做点什么”的事，不论来自哪里，都汇到同一个列表：

| 来源 | 例子 |
|---|---|
| Claude Code / Codex 钩子 | 等你批准一次文件写入、一条命令；`AskUserQuestion`；计划等你确认 |
| 桌面 App 的会话 | 一轮结束时留给你的下一步问题 |
| agent-autoloop 的卡片 | 后台 Agent 拿不准、要你拍板的事 |
| AI 规划 | 排计划时真正拿不准、会影响安排的问题 |
| 邮件 | 需要回复、有截止日的邮件 |
| 截止日 | 三天内到期的事项 |
| GitHub | 等你 review 的 PR、默认分支 CI 失败 |
| 小纸条 | 另一半在记账页写给你的事 |
| AI 代办 | 交给 Agent 的事做完了，等你看成果 |

每一项都有选项按钮，在阅读器上点一下或在手机上点一下就算回答；回答会送回来源（例如批准 Agent 的操作、把计划问题的答案合并进计划）。紧急项会让阅读器轻响一声，夜间静音。

设计原则：**宁可漏报低优先级，也不让列表变成噪音**。邮件经过 AI 筛选，只留真正要处理的；同一个 CI 失败只报一次，新的推送再失败才再报。

## 6. AI 层

AI 在这里不是聊天对象，而是一个后台整理员。它做这几件事：

| 功能 | 触发 | 产出 |
|---|---|---|
| 今日计划 | 每次快速捕获或回答问题 | 主线、避开日程的时间块、带优先级和预估时长的待办、拿不准的问题 |
| 简报 | 早、午、傍晚各一次 | “现在做什么”、三件要事、提醒 |
| 邮件筛选 | Mac 上传新邮件时 | 只留需要回复、有截止日、来自重要的人的 |
| 研究焦点 | 每天早上或笔记变化时 | 从最近的笔记、Agent 会话、捕获里归纳你正在推进的问题 |
| 论文雷达 | 每天上午 | 当天 arXiv 新论文里和研究焦点相关的最多 3 篇；点“有用/无关”会影响下一次排序 |
| Agent 摘要 | 一轮 Agent 会话结束 | 一句话说做完了什么 |
| 近况观察 | 每晚 | 当天计划、完成、邮件和 Agent 的流水 |

### 记忆分层

1. **原始输入**（捕获、邮件、笔记）：只追加，作为证据保留，计划和记忆都能从它重建。
2. **今日计划**：每次补充都增量合并，没做完的自动带到第二天。
3. **长期记忆**：结构化事实（主语、谓语、值、原话证据、置信度、重要度）。事实变了，旧的标成历史而不是覆盖；清晰度随时间衰减，置顶的不衰减。
4. **研究焦点**和**反馈**：给论文雷达和简报用。

所有记忆都能在编辑器里查看、置顶、修改、删除。

### 省 Token

- 每次调用只带按 token 预算裁剪过的记忆视图；
- 计划是增量合并，不是每次重写一天；
- 结果缓存在 D1，模型只在有新输入或固定时间点运行；
- 简单任务（解析待办、记账、Agent 摘要）用低思考强度。

### 外部内容只是资料

邮件、笔记、网页、小纸条、Agent 输出进入提示词时都包在“资料”里，系统提示明确告诉模型：这些内容里出现的任何指令都不执行。交给 Agent 的代办也有同样的规则：只起草、不替你发送；对外发出、花钱、改系统设置之前必须先问。

## 7. 输入在手机上，不在墨水屏上

墨水屏上打字是折磨。所以输入全部放在手机网页（加到主屏幕，像 App 一样用）：

- **`/c` 今天**：把想做的事一口气说出来（用键盘的语音输入），AI 排进计划；回答 AI 的问题；勾待办；处理邮件；把能交给 AI 的事一键派给 Mac 上的 Agent。
- **`/m` 记账**：说一句“午饭 18”“房租每月 3000 我们一起”，AI 拆成一次性花费和固定支出。见 [ledger.md](ledger.md)。

阅读器上只保留点按：勾待办、点选项、翻页、强制刷新。

## 8. Agent 监控

Agent 会话的状态来自好几个地方，各取所长：

- **Claude Code / Codex 钩子**：开始、每次工具调用、等批准、结束，异步上报，不拖慢 Agent。远程服务器上装同一个钩子，SSH 会话也能看到。
- **桌面 App 的会话存储**：拿到会话的人类可读标题（钩子只知道目录名），以及一轮结束时留给你的问题。
- **没有钩子的 Agent**（比如 DeepSeek Harness）：读它的会话日志，推断开始、工具调用、等批准、结束。
- **agent-autoloop**：后台规则派出去的任务和它们的卡片。

看板上每个会话显示标题、当前步骤、工具调用数和本轮耗时；等你的会话会出现在“需要你”。见 [agents.md](agents.md)。

## 9. 两个人的账本

记账最难的不是记，是坚持记。所以：

- 只需要说一句话，AI 负责拆分金额、币种、分类、是否共同、谁付的；
- 每周、两周、每月、每年的开销说一次就够，以后按周期自动计入；
- 两个人各用自己的手机记，共同开销各担一半，页面算出谁该给谁多少；
- 另一位的页面可以换成可爱的主题，配自己喜欢的吉祥物图片；页面上还有一个“使唤”按钮，写的小纸条会进看板主人的“需要你”、待办和日历。

试过接银行和支付平台的通知或开放银行接口，个人用户门槛太高、覆盖不全，最后回到“说一句话”这条最简单的路。

## 10. 走过的弯路

- **全屏 PNG 方案**：设计很漂亮，但不能点按、实时性差，放弃。
- **在墨水屏上做输入**：键盘慢、残影重，全部挪到手机。
- **让 AI 每次重写整天计划**：Token 消耗大，而且会丢掉用户手动改过的东西；改成增量合并。
- **用“有没有收到邮件”判断邮箱是否连上**：没邮件时会误报未连接；改成单独记录同步时间。
- **只靠钩子监控 Agent**：桌面 App 的会话没有标题、问题也拿不到；补上读会话存储。

## 11. 可以继续做的

- 更多墨水屏设备的刷新接口适配（欢迎提交 `tools/probe` 的输出）；
- 彩色墨水屏的配色；
- 多人家庭的账本（现在是两个人）；
- 本地大模型作为 AI 层的替代。
